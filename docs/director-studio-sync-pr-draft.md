# DRAFT PR: two-way sync between Studio and Director

Status: draft for chingon (polish/final-pass). Nothing here is built yet. Written 2026-11-11 from the main checkout
(video/cinematic-intro-hq at bf5337a4).

## Why

Vico edits environments, props and people in the Director, then wants those edits in Studio. He also wants to edit in
Studio and push to the Director, with both open in separate tabs at the same time, in whichever direction suits the moment.
Today only one direction exists, and only for props.

## What exists now (verified in the code)

- One shared state for every browser tab on :3000. `tools/studio-server.mjs` owns `studio-state.json` and the
  `/api/studio-state` endpoints. `tools/studio-state/sync.js` is injected into every HTML page, pulls the state at load, and
  pushes each `ergoflex*` localStorage write with a merge base. Two tabs on the same server share it.
- Studio pages show a "N shared edits from X, Reload to see" badge (polls every 5 s). The Director does not: its stage is
  an iframe (`experience/index.html`, `?presentation=1`) whose storage is in memory and which skips `sync.js`, so the
  Director only sees Studio's state as it was when the Director page loaded.
- Director to Studio, props only: Props tab, "Make permanent in Studio..." (`experience/scene-prop-editor.mjs`
  `makePermanent`, `experience/prop-edits.mjs` `writeSceneAssets`) writes `ergoflex.sceneAssets.v1` for the chapter's room.
  It refuses props the film itself also moves, and props added on the desk.
- Director edits otherwise live in the cut (`ergoflex.clientCuts.v1`) per chapter: `propEdits`, `peopleEdits`, `lightEdits`,
  `lights`, `deskEdits` (size, pose, initial height and tilt, clips, build), branding. They are overlays on whatever
  Studio holds.

## What Studio can hold today

| Director domain | Studio key | Can Studio hold it? |
|---|---|---|
| Room props: move, turn, scale, hide, add | `ergoflex.sceneAssets.v1` | Yes (already pushed) |
| Other ErgoFlex desks: size, place, build | `ergoflex.sceneDesksBySizeV2`, `ergoflex.sceneDesksV1` | Yes; no Director push yet |
| People (cast, poses, colours) | none. Generated by `room-people.mjs` from the room mode and time of day. Saved poses only: `ergoflex.peoplePoses.v1` | No |
| Lights (edited, added) | none. `sceneLights` is rebuilt from the room profile each time | No |

## Proposed work

### Phase 1: props and desks both ways, two tabs working (no render cost)

1. **Director to Studio, desks.** In the Desks tab, "Make permanent in Studio..." beside the props one. Same confirm-each-row
   dialog. Writes the chapter's desk size, place and build into Studio's scene-desk records for the room. Blocked rows, with
   the reason shown: the featured desk, desks the film also moves, desks with choreography clips (clips stay chapter edits).
2. **Studio to Director, "Refresh from Studio".** A Director button that re-reads `/api/studio-state` into the stage
   without losing the open chapter's edits or the undo history. Show a "Studio changed: N edits, Refresh" badge in the Director
   using the existing `/api/studio-state/changes?since=` poll (add it to the Director page, which is the same-origin parent,
   not the iframe). Must not use a second EventSource per tab (see the 6-connection trap in memory).
3. **Studio to Director, "Adopt Studio's version".** When Studio has changed a prop or desk the chapter also overrides, list
   those conflicts and let Vico choose per item: keep the chapter's edit, or drop it and take Studio's. Without this, a Studio
   edit is invisible in a chapter that already moved the same prop.
4. **Studio, "Send to Director" (optional).** A button in the Studio toolbar that opens `/experience/` on the current room and
   chapter, so the hand-off is one click; the state is already shared through the server.
5. **Tests.** Extend `tests/director-props-e2e.mjs`; new `tests/director-studio-sync-e2e.mjs` that runs a Studio tab and a
   Director tab against one `--no-watch` server with a temp state file: edit in Studio then Refresh in the Director; edit in the
   Director then Write to Studio and see it in Studio after reload; conflict list; undo after a Refresh.

### Phase 2: people and lights (Studio needs new storage; render-epoch decision first)

- Studio would need a saved cast per room (`ergoflex.roomCast.v1`: the Director `peopleEdits.cast` shape) and saved lights per
  room (the `lights` / `lightEdits` shape), both applied by `room-people.mjs` and the light rig when present.
- This changes how Studio rooms render and may move the film's pixels. **Do not merge without Vico's go-ahead on the
  render epoch** (`tools/experience/render-epoch.txt`, currently 2).
- Do Phase 1 first; Phase 2 only after Vico has used it.

## Risks to check

- The 6-connections-per-host trap: each :3000 HTML page holds an EventSource and Director pages hold two. Studio + Director
  in two tabs is within the limit, but more tabs hit "Preparing your digital twin". The refresh must not open more.
- `sync.js` merge: two tabs saving the same `sceneAssets` room entry is last-writer-wins per room. A Director write while
  Studio has unsaved edits must use the write base (as `makePermanent` already does) so Studio's other rooms survive.
- `studio-state.json` is committed. Tests must use a temp state file, never Vico's live one (he has local edits in it).
- Prop and desk ids must match between the stage and Studio (`sceneAssetKey`, desk record ids). Rows that cannot be mapped
  stay blocked, as in the props dialog.

## Out of scope

- Branding, music, LED and film-only data (titles, camera) stay Director-only.
- No change to render output in Phase 1.

## Acceptance for Phase 1

- Both tabs open on :3000: a Studio prop or desk edit shows in the Director after one click on Refresh, chapter edits intact.
- A Director prop or desk edit written with "Make permanent in Studio..." shows in Studio's badge and after reload.
- Conflicts are listed, never silently overwritten.
- Film check: frames identical to the baseline; epoch unchanged.
